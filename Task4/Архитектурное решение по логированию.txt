- Планирование
    Сбор логов необходимо производить со всех сервисов и хостов системы:
    1. Хосты (утилизация)
    2. CRM - фронт и бэк
    3. MES - фронт и бэк
    4. Shop - фронт и бэк
    5. БД
    6. RabbitMQ

    Список логирования на начальном этапе может включать основные этапы прохождения заказа, и включать в себя дату и время статуса заказа, номер заказа,
    дата заказа, текущий статус и возможная ошибка.

    Уровни логирования можно изменять в зависимости от окружения, в проде используем уровень INFO для всех логов, и уровень TRACE для ошибок.
    В среде разработки и тестирования уровень логирования можно при необходимости использовать TRACE или DEBUG.

- Мотивация
    Правильно организованное логирование позволит получить точное описание места и время возникновения проблемы и в дальнейшем как вариант воспроизведение
    проблемы в тестовой среде и устранение. Логирование поможет выделить проблемные сервисы и сосредоточить усилия на критических проблемах. Метрики потери заказов
    или "медленные" обработки смогут быть идентифицированы и обработаны.

    В связи с тем что ресурсы разработки ограничены, в первую очередь реализуем сервисы взаимодействия с потребителями SHOP API и MES API, чтобы была возможность повышения
    качества внешних ресурсов.

- Предлагаемое решение

    Для реализации логирования SHOP API и MES API, предлагаю использовать стек ELK, позволяющий собирать, хранить и индексировать, а в дальнейшем и визуализировать логи.
    Доступ к логам необходимо закрепить соответствующими документами, настроить доступы из VPN и подключить сервисы к серверу безопасности.
    Политика логов зависит от законодательства. Для удобства и оптимального хранения, можно реализовать горячее хранение логов за 2 недели, холодное в отдельном
    индексе за 3 месяца, в архивном индексе за 5 лет и дальнейшее удаление.

    При использовании стека ELK, с помощью компонента Kibana можно визуализировать логи в удобном виде а также настроить все необходимые алерты и выявление аномалий с помощью языка запросов.

- Дополнительное задание

| Критерий          | ELK (Elastic Stack)                          | OpenSearch                                   | Splunk                                      | Grafana Loki                               |
|--------------------|----------------------------------------------|---------------------------------------------|---------------------------------------------|--------------------------------------------|
| **Лицензия**       | Elastic License (некоторые компоненты SSPL)  | Apache 2.0 (полностью открытая)             | Проприетарная (бесплатная версия с ограничениями) | Apache 2.0                              |
| **Масштабируемость** | Высокая, но требует настройки под нагрузку   | Высокая, оптимизирована для больших данных | Очень высокая, но требует дорогих лицензий | Высокая для чтения, слабее для записи     |
| **Скорость поиска** | Быстрый (с индексацией)                      | Сопоставима с ELK                           | Экстремально быстрый (проприетарные алгоритмы) | Медленнее (индексирование меток, не содержимого) |
| **Стоимость**       | Бесплатен, но платные функции в Elastic Cloud | Полностью бесплатен                         | Очень дорогой (плата за объем данных)      | Бесплатен, низкая стоимость хранения      |
| **Интеграция**      | Широкая (Beats, Logstash, Kibana)            | Совместим с Elasticsearch API               | Множество готовых коннекторов              | Лучше всего работает с Grafana             |
| **Сложность развертывания** | Средняя (требует настройки)                | Средняя (проще, чем ELK)                    | Низкая (но требует лицензирования)         | Низкая (легковесный агент)                |

Обоснование выбора:
1. **ELK**
   *Плюсы*: Гибкость, мощная аналитика, поддержка множества плагинов.
   *Минусы*: Сложность настройки кластера, лицензионные ограничения для коммерческого использования.

2. **OpenSearch**
   *Плюсы*: Полная открытость, совместимость с Elasticsearch API.
   *Минусы*: Меньше готовых решений по сравнению с Elastic Stack.

3. **Splunk**
   *Плюсы*: Скорость, удобный интерфейс, корпоративная поддержка.
   *Минусы*: Очень высокая стоимость, проприетарная модель.

4. **Grafana Loki**
   *Плюсы*: Экономичное хранение, интеграция с Grafana, простота.
   *Минусы*: Менее эффективен для сложных запросов к телу логов.

Для баланса функциональности и стоимости — **ELK** (если нет лицензионных ограничений).
